# 多语言支持配置指南

## 概述

本指南详细说明了如何在项目中添加新的国家语言支持。本项目基于 `i18next` 和 `react-i18next` 实现国际化。

目前支持的语言：
- `en` - 英语
- `zh-Hans` - 简体中文
- `pt` - 葡萄牙语

## 添加新语言支持

### 步骤一：创建翻译文件

在 `src/i18n/lang/` 目录下创建新的语言文件。

#### 1.1 复制现有翻译文件

以英语版本为模板，创建新语言文件：

```bash
# 例如：添加西班牙语 (es)
cp src/i18n/lang/app.en.ts src/i18n/lang/app.es.ts
cp src/i18n/lang/common.en.ts src/i18n/lang/common.es.ts
cp src/i18n/lang/time.en.ts src/i18n/lang/time.es.ts
cp src/i18n/lang/tools.en.ts src/i18n/lang/tools.es.ts
```

#### 1.2 翻译文案内容

打开新建的 `.es.ts` 文件，翻译其中的文本内容：

```typescript
const translation = {
  common: {
    welcome: '¡Hola! Soy tu asistente de IA, feliz de ayudar.',
    // ... 其他翻译
  },
  // ... 其他模块
}
```

**⚠️ 注意事项**：
- 保持所有 `key` 的层级结构完全一致
- 不能遗漏任何 `key`
- 翻译要准确、符合当地语言习惯

### 步骤二：配置 i18next

编辑 `src/i18n/i18next-config.ts` 文件。

#### 2.1 导入新语言文件

在文件顶部添加导入语句：

```typescript
// 现有导入...
import commonZh from './lang/common.zh'
import commonPt from './lang/common.pt'
import commonEs from './lang/common.es'  // 新增西班牙语

import appZh from './lang/app.zh'
import appPt from './lang/app.pt'
import appEs from './lang/app.es'  // 新增西班牙语

import toolsZh from './lang/tools.zh'
import toolsPt from './lang/tools.pt'
import toolsEs from './lang/tools.es'  // 新增西班牙语

import timeZh from './lang/time.zh'
import timePt from './lang/time.pt'
import timeEs from './lang/time.es'  // 新增西班牙语
```

#### 2.2 在 resources 中添加语言配置

在 `resources` 对象中添加新语言：

```typescript
const resources = {
  'en': {
    translation: {
      common: commonEn,
      app: appEn,
      tools: toolsEn,
      time: timeEn,
    },
  },
  'zh-Hans': {
    translation: {
      common: commonZh,
      app: appZh,
      tools: toolsZh,
      time: timeZh,
    },
  },
  'pt': {
    translation: {
      common: commonPt,
      app: appPt,
      tools: toolsPt,
      time: timePt,
    },
  },
  // 新增西班牙语配置
  'es': {
    translation: {
      common: commonEs,
      app: appEs,
      tools: toolsEs,
      time: timeEs,
    },
  },
}
```

### 步骤三：更新类型定义

编辑 `src/i18n/index.ts` 文件，在 `locales` 数组中添加新语言：

```typescript
export const i18n = {
  defaultLocale: 'en',
  locales: ['en', 'zh-Hans', 'pt', 'es'], // 添加 'es'
} as const

export type Locale = typeof i18n['locales'][number]
```

### 步骤四：使用新语言

#### 4.1 切换语言

```typescript
import { changeLanguage } from '@/i18n/i18next-config'

// 切换到西班牙语
changeLanguage('es')
```

#### 4.2 在组件中使用

```typescript
import { useTranslation } from 'react-i18next'

function MyComponent() {
  const { t } = useTranslation()

  return <div>{t('common.welcome')}</div>
}
```

## Android平台返回值优化

### 问题背景

在Android平台上，原生方法可能返回JSON字符串，但前端代码期望接收对象。若不做处理，直接使用会导致类型错误。

### 解决方案

在 `src/hooks/useNativeBridge.js` 中添加 `parseAndroidResponse` 辅助函数：

```javascript
export function useNativeBridge() {
  // 辅助函数：解析Android平台返回值
  const parseAndroidResponse = (data) => {
    if (typeof data === 'object') return data
    if (typeof data === 'string') {
      try {
        return JSON.parse(data)
      } catch {
        console.warn('[Android Bridge] 返回值解析失败，将返回原始字符串:', data)
        return data
      }
    }
    return data
  }

  const callNativeMethod = (methodName, params, callbackName) => {
    return new Promise((resolve, reject) => {
      // ... 验证逻辑 ...

      try {
        // ... 其他平台 ...

        else if (window.Android) {
          // 回调模式
          if (typeof callbackName === 'string') {
            window[callbackName] = (data) => {
              resolve(parseAndroidResponse(data))  // 使用 parseAndroidResponse
            }
          }

          // 同步调用模式
          if (methodName === 'jsToNative') {
            const res = Android[methodName](JSON.stringify(params))
            resolve(parseAndroidResponse(res))  // 使用 parseAndroidResponse
          }
          else {
            const res = Android[methodName]()
            resolve(parseAndroidResponse(res))  // 使用 parseAndroidResponse
          }
        }
        // ...
      }
      catch (err) {
        console.error(`useNativeBridge:methodName:${methodName}`, err)
        reject(err)
      }
    })
  }

  // ... 其他 hooks ...
}
```

### 工作原理

1. **类型检查**：首先检查数据类型
2. **字符串解析**：如果是字符串，尝试 `JSON.parse()`
3. **错误处理**：解析失败时返回原字符串并警告
4. **对象透传**：如果已是对象，直接返回

## 常见问题

### Q1: 翻译文件中的某个 key 缺失会怎样？

**A**: 如果在翻译文件中遗漏了某个 `key`，在切换到该语言时，未翻译的文本将显示为该 `key` 的名称（如 `common.welcome`）。建议使用 `fallbackLng: 'en'` 作为回退语言。

### Q2: 新语言的文件名后缀有什么要求？

**A**: 文件命名规则为 `{模块名}.{语言代码}.ts`，其中：
- `语言代码` 使用标准的语言标识符（如 `en`, `zh`, `pt`, `es` 等）
- 对于简体中文，约定使用 `zh-Hans`

### Q3: 如何验证翻译是否完整？

**A**: 可以编写脚本对比各语言文件的 `key` 结构，确保一致性。另外，在开发环境下，`i18next` 会输出调试信息，帮助发现缺失的翻译。

### Q4: Android 平台返回 JSON 字符串但解析失败怎么办？

**A**: `parseAndroidResponse` 函数会在解析失败时返回原始字符串，并输出警告日志。可以在控制台查看具体错误信息，排查问题。

### Q5: 添加新语言后需要重新启动开发服务器吗？

**A**: 是的，需要重启开发服务器以加载新的翻译文件配置。

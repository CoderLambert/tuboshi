# 停止聊天消息 API 测试演示脚本

## 演示目标

展示如何使用测试页面来验证 `POST /api/chat-messages/[taskId]/stop` API 端点的功能。

## 演示环境

- **页面地址**: <http://localhost:3001/test/stop-message>
- **浏览器**: Chrome/Firefox（推荐开启开发者工具）
- **网络**: 确保后端服务正常运行

## 演示步骤

### 第一步：页面介绍和准备

1. **打开测试页面**

   ```
   访问: http://localhost:3001/test/stop-message
   ```

2. **页面布局介绍**
   - 左侧：测试控制面板
   - 中间：消息历史显示
   - 右侧：API 调用监控

3. **开启开发者工具**
   - 按 F12 打开开发者工具
   - 切换到 Console 面板查看日志
   - 切换到 Network 面板监控网络请求

### 第二步：开始 API 监控

1. **启动监控**
   - 在右侧 API 监控面板中点击"开始监控"按钮
   - 确认按钮变为"停止监控"，表示监控已启动

2. **监控说明**
   - 监控将记录所有的 HTTP 请求
   - 特别关注 `/api/chat-messages` 相关的请求
   - 可以查看请求和响应的详细信息

### 第三步：准备测试数据

1. **设置会话ID**

   ```
   在"会话ID"输入框中输入: new
   ```

   > 使用 "new" 将创建一个新的会话

2. **输入测试消息**

   ```
   在"消息内容"输入框中输入:
   请详细解释人工智能的发展历史，包括各个重要阶段、关键技术突破、主要研究机构和学者的贡献，以及对社会产生的影响。请尽可能详细地描述每个阶段的特点和重要事件，并分析未来的发展趋势。
   ```

   > 使用较长的消息确保有足够时间测试停止功能

### 第四步：发送消息并获取 taskId

1. **发送消息**
   - 点击"发送消息"按钮
   - 观察按钮状态变为"发送中..."

2. **观察状态变化**
   - 查看状态面板中的"响应状态"变为"正在响应"
   - 等待"任务ID"字段显示具体的 taskId 值
   - 观察消息历史中出现用户消息和开始的助手响应

3. **监控 API 调用**
   - 在 API 监控面板中查看 `POST /api/chat-messages` 请求
   - 点击请求详情查看请求体和响应信息
   - 确认请求成功（状态码 200）

### 第五步：测试停止功能

1. **等待合适时机**
   - 等待助手开始响应（消息历史中出现助手消息）
   - 确保"停止消息"按钮变为可点击状态（红色）
   - 确认状态面板中显示有效的 taskId

2. **执行停止操作**
   - 点击"停止消息"按钮
   - 立即观察各个面板的变化

3. **验证停止结果**
   - 查看消息历史中是否出现"✅ 消息已成功停止"的系统消息
   - 确认助手的响应立即停止（不再更新）
   - 查看状态面板中"响应状态"变为"空闲"
   - 确认"任务ID"重置为"无"

### 第六步：验证 API 调用

1. **查看停止 API 请求**
   - 在 API 监控面板中找到 `POST /api/chat-messages/[taskId]/stop` 请求
   - 点击展开查看请求详情

2. **验证请求信息**

   ```json
   请求方法: POST
   请求URL: /api/chat-messages/[具体的taskId]/stop
   请求体: {
     "user": "abc-123"
   }
   响应状态码: 200 (成功)
   ```

3. **检查响应内容**
   - 查看响应体内容
   - 确认没有错误信息
   - 记录响应时间

### 第七步：测试边界情况

1. **测试重复停止**
   - 尝试再次点击"停止消息"按钮
   - 应该显示"没有正在进行的任务可以停止"的提示

2. **测试无 taskId 停止**
   - 清空消息历史
   - 直接点击"停止消息"按钮
   - 按钮应该是禁用状态

3. **测试短消息**
   - 输入简短消息如"你好"
   - 发送后快速尝试停止
   - 观察是否能成功停止或消息已完成

## 演示要点

### 成功指标

✅ **消息发送成功**

- API 监控显示 `POST /api/chat-messages` 请求成功
- 获取到有效的 taskId
- 助手开始响应

✅ **停止功能正常**

- 停止按钮在适当时候可点击
- API 监控显示 `POST /api/chat-messages/[taskId]/stop` 请求成功
- 消息响应立即停止
- 状态正确更新

✅ **错误处理正确**

- 边界情况处理得当
- 错误信息清晰明确
- 不会导致页面崩溃

### 关键观察点

1. **taskId 的获取和传递**
   - taskId 必须从消息发送 API 的响应中正确获取
   - 停止 API 必须使用正确的 taskId

2. **时序控制**
   - 停止按钮只在有活动任务时启用
   - 停止操作的时机很重要

3. **状态同步**
   - UI 状态与实际 API 状态保持同步
   - 错误状态能正确反映和恢复

### 常见演示问题

❌ **taskId 未获取**

- 检查消息发送 API 是否成功
- 确认 API 响应格式正确

❌ **停止按钮无法点击**

- 确保消息正在响应中
- 检查 taskId 是否有效

❌ **停止无效果**

- 验证停止 API 调用是否成功
- 检查后端实现是否正确

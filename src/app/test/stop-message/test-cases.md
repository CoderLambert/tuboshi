# 停止聊天消息 API 测试用例

## 测试目标

验证 `POST /api/chat-messages/[taskId]/stop` API 端点的功能是否正常。

## 测试环境

- 页面路径: `/test/stop-message`
- API 端点: `POST /api/chat-messages/[taskId]/stop`
- 依赖服务: 聊天消息发送 API

## 测试用例

### 用例 1: 正常停止流程

**目标**: 验证在消息响应过程中能够成功停止消息生成

**步骤**:

1. 在会话ID输入框中输入有效的会话ID（或输入 "new" 创建新会话）
2. 在消息内容输入框中输入较长的问题，例如：

   ```
   请详细解释人工智能的发展历史，包括各个重要阶段、关键技术突破、主要研究机构和学者的贡献，以及对社会产生的影响。请尽可能详细地描述每个阶段的特点和重要事件。
   ```

3. 点击"发送消息"按钮
4. 等待系统获取到 taskId（在状态面板中可以看到）
5. 在消息开始响应时，立即点击"停止消息"按钮
6. 观察API调用结果和消息状态变化

**预期结果**:

- 消息发送成功，获取到有效的 taskId
- 停止API调用成功，返回状态码 200
- 消息响应立即停止
- 系统状态更新为"空闲"
- 显示成功停止的提示信息

### 用例 2: 无效 taskId 测试

**目标**: 验证当 taskId 无效时的错误处理

**步骤**:

1. 不发送消息，直接尝试点击"停止消息"按钮

**预期结果**:

- 按钮应该是禁用状态
- 显示"没有正在进行的任务可以停止"的提示

### 用例 3: 消息已完成后停止测试

**目标**: 验证消息已完成后尝试停止的处理

**步骤**:

1. 发送一个简短的消息，等待完全响应完成
2. 尝试点击"停止消息"按钮

**预期结果**:

- 按钮应该是禁用状态
- 显示"当前没有正在响应的消息"的提示

### 用例 4: 网络错误处理测试

**目标**: 验证网络错误时的错误处理

**步骤**:

1. 在浏览器开发者工具中模拟网络错误
2. 发送消息并尝试停止

**预期结果**:

- 显示相应的错误信息
- 系统状态正确更新
- 不会导致页面崩溃

## 验证要点

### API 调用验证

1. **发送消息 API**:
   - 端点: `POST /api/chat-messages`
   - 请求体包含正确的字段
   - 响应是 Server-Sent Events 流
   - 能够正确获取 taskId

2. **停止消息 API**:
   - 端点: `POST /api/chat-messages/[taskId]/stop`
   - taskId 参数正确传递
   - 请求体格式正确
   - 响应状态码为 200（成功）或相应的错误码

### 用户界面验证

1. **状态显示**:
   - 当前会话ID显示正确
   - taskId 在获取后正确显示
   - 响应状态和加载状态准确反映当前情况

2. **按钮状态**:
   - 发送按钮在适当时候禁用/启用
   - 停止按钮只在有活动任务时启用

3. **消息历史**:
   - 用户消息正确显示
   - 助手响应实时更新
   - 系统消息（如停止成功）正确显示

### 错误处理验证

1. **网络错误**:
   - 显示用户友好的错误信息
   - 不会导致页面崩溃
   - 状态正确重置

2. **API 错误**:
   - 正确处理各种HTTP状态码
   - 显示具体的错误信息
   - 记录详细的调试信息

## 常见问题排查

### 问题 1: 无法获取 taskId

**可能原因**:

- 消息发送失败
- API响应格式不正确
- 网络连接问题

**排查方法**:

- 检查网络面板中的API调用
- 查看控制台错误信息
- 验证后端服务状态

### 问题 2: 停止API调用失败

**可能原因**:

- taskId 无效或已过期
- 后端服务异常
- 权限问题

**排查方法**:

- 验证 taskId 的有效性
- 检查API响应状态码和错误信息
- 确认后端服务正常运行

### 问题 3: 消息没有停止

**可能原因**:

- API调用成功但后端处理失败
- 消息已经接近完成
- 缓存或延迟问题

**排查方法**:

- 检查API响应确认调用成功
- 观察消息是否在短时间内停止
- 查看后端日志（如果可访问）
